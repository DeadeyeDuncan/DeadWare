# DeadWare Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Ship a real Windows monitoring application and public source repository.

**Architecture:** A single background collector publishes immutable snapshots to shared bounded history. WPF main, detached graph, and widget windows subscribe to that state. Pure history/rate/settings logic is isolated from hardware APIs for testing.

**Tech Stack:** C#/.NET 10 LTS, WPF, LibreHardwareMonitorLib 0.9.6, Microsoft.Diagnostics.Tracing.TraceEvent 4.0.0, xUnit; GitHub Actions.

**Spec:** docs/superpowers/specs/2026-10-25-deadware-design.md

## Global Constraints
- Windows 10/11 x64 first, self-contained release; do not claim ARM64 validation.
- Real readings only; unavailable values are nullable and charts preserve gaps.
- Four CPU/GPU graphs, shared-scale two-series network graph, app network table, pop-outs and widget.
- Broad hardware discovery, selectable GPU, shared collector, bounded 900-second history.
- Normal user by default; ETW may require explicitly requested elevation. No protection bypass or custom driver installation.
- Local data only; no packet payload capture. Exclude logs, settings, build output and local mockups from GitHub.
- Public DeadeyeDuncan/DeadWare. User approved creation/publication. Native-looking icon in Dead app family.

## Review Focus
1. Unavailable and invalid readings stay unknown and leave chart gaps.
2. Counter resets or non-positive elapsed times cannot produce misleading or infinite rates.
3. Multi-GPU IDs and reused PIDs do not mix device/application histories.
4. Poll failures, ETW failure and permission denial remain visible without crashing UI.
5. Corrupt settings and removed monitors cannot strand or crash windows.
