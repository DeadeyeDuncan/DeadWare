# Storage (0.11.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add drive health, temperature, live read/write throughput and free space to DeadWare as an Overview card, a Storage page, a widget graph, six-hour cached traces and Cooling Health devices.

**Architecture:** A hybrid data layer. `WindowsStorage` enumerates drives through WMI and reads `PhysicalDisk` counters plus `DriveInfo` on the collector thread every poll. `StorageSensorLoop` polls a dedicated LibreHardwareMonitor `Computer` with only storage enabled every 30 seconds behind a new `StorageSensors` setting and publishes per-drive health. Both land on `Reading.Storage`; existing projections (graph history, thermal) and chart code are extended by kind, never forked.

**Tech Stack:** .NET 10, WPF, LibreHardwareMonitorLib 0.9.6, `System.Diagnostics.PerformanceCounter`, `System.Management` (new package), SQLite via existing stores, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-03-storage-design.md`

## Global Constraints

- Metric keys: `storage/{id}/read`, `storage/{id}/write`, `storage/{id}/active`, `storage/{id}/volume/{letter}/free`, `storage/{id}/temperature`, `storage/{id}/life`, `storage/{id}/used`. `{id}` is the serial, else `{model}#{index}`.
- Null, never zero, for any unavailable reading.
- At most 8 drives persisted or offered to Cooling Health; drives without a serial or removable drives are live-only.
- Slow path period 30 seconds; per-hardware timeout 5 seconds; quit joins under the existing 5-second hardware budget.
- WMI re-enumeration every 60 seconds; counter failure status after 60 seconds: `Disk counters unavailable`.
- Settings: `StorageSensors`, default `true`, restart to apply. Copy: **Storage sensors (temperature and health; restart to apply)**.
- Unavailable copy: `Unavailable · storage sensors off`, `Unavailable · sensor timeout`, `Unknown · needs administrator`, `No drives detected`.
- Health badges: `OK`, `Warning`, `Failing`, `Unknown`.
- Version 0.11.0; CHANGELOG heading `## 0.11.0 — Storage`.
- Follow `AGENTS.md`: commit per task, push, PR against `main`.

## Review Focus

1. A drive whose WMI serial contains whitespace or is empty string (`"   "`) must be treated as no serial, not as id `"   "`. Test in Task 1.
2. Two drives with the same model and no serial must get distinct ids (`model#0`, `model#1`) and both stay live-only. Test in Task 1.
3. A counter instance named `_Total` or one with no drive letters (`"2"`) must map to the right drive or be ignored, never summed twice. Test in Task 2.
4. Plugging in a USB drive mid-session changes the drive list; cached mappings must not change identity for the fixed drives. Test in Task 4.
5. The slow loop must never block the collector poll: a 5-second hang in LibreHardwareMonitor must not delay `SampleAvailable`. Test in Task 3.

Matching in the loop: by `StorageProjection.Normalize(serial)` against `drive.Serial`, then by `Index`, then by `Model` when exactly one drive has that model; unmatched readings become `StorageHealth` with `DriveId = "unmatched:"+model`. When `StorageSensors` is off the collector does not construct the loop and every `Persistable` drive gets `Health` with `Unavailable="Unavailable · storage sensors off"`. A `Read` that exceeds `perHardwareTimeout` for one hardware yields `Unavailable="Unavailable · sensor timeout"` for that drive only.

`LibreStorageHealth.Read` for each `HardwareType.Storage` hardware: `Serial` and `Index` from the hardware when `LibreHardwareMonitorLib` 0.9.6 exposes them on the concrete storage type (check `AbstractStorage` members first; fall back to the trailing number of `Identifier` for `Index` and null for `Serial`); temperature from sensor `Temperature`, life from `Level` sensor `Remaining Life`, used from `Load` sensor `Used Space`, `CriticalWarning` and the three ATA counts from the SMART data where the library exposes them, otherwise zero with `Readable` true if any sensor had a value. `NeedsAdministrator` is true when the hardware reports no sensors at all and the process is not elevated.
