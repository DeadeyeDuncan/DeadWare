# 0.14.1 Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.14.1, the cleanup release the user approved on 2026-11-06: eight fixes to the 0.13.0 and 0.14.0 Processes and history features, with their docs and stronger tests, and no new features.

**Architecture:** Each fix stays in the component that has the defect. `Collector.RunAsync`'s `finally` stops the disk trace. `ProcessActions` reads file attributes through `IProcessControl`. `MainWindow`'s bubbling KeyDown forwards keys to `ProcessesPage.PageKey`. `Reading` serializes a count in place of the per-app list, and `App.DiagnosticReport` builds the report. `ProcessHistory.SavedName` is shared by the minute folder and the store. Usage history gets a cursor time owned by the page. The Application resources card updates its rows in place, as the Processes page does. Docs and tests come last.

**Tech Stack:** .NET 10, WPF, System.Text.Json, Microsoft.Data.Sqlite (existing), xUnit 2.9.3. No new packages.

**Spec:** `docs/superpowers/specs/2026-11-05-processes-design.md` covers the Processes and history features this release touches. 0.14.1 has no spec of its own: the Scope section below is its requirement. Each task updates the spec where it changes behaviour.

## Scope (approved 2026-11-06)

1. **The disk trace stops with the collector's worker.** `Collector.RunAsync` can end after an error it cannot publish past, or on cancellation. Either way it stops the disk trace as it already stops the network trace, so no `DeadWare-Disk-<pid>-*` session outlives the worker. If a start is still running, it finishes and is then stopped. Disposal's stop is the same task. The status copy is unchanged.
2. **Open file location: denied is not gone.** The existence check goes through `IProcessControl` and reads attributes the way `File.GetAttributes` does, long paths included.
   - Windows reports the file or a folder on its path not found, or a folder sits at the path: "The program file is no longer there." (unchanged).
   - Windows denies access: "Could not open the file location (denied by Windows)." Nothing is revealed.
   - Any other read failure: the existing "Could not open the file location (<exception type>)."
3. **Processes keys from the shell.** While the Processes page is shown, Ctrl+F (focus the search box), F5 (re-sort) and Esc (clear a non-empty search) also work when keyboard focus is in the sidebar, in the header or on the window itself. The following are unchanged:
   - keys pressed inside the page or in pop-ups (menus, the column picker);
   - keys a control already handled;
   - the table's own keys (Left, Right, Enter, Delete and navigation);
   - every other page.
4. **Diagnostics hold no app names.** The list is removed, not made opt-in. `--diagnose` samples no longer contain `Reading.Processes` (image names, PIDs and traffic). Each sample carries `NetworkApplications`, the number of processes with attributed traffic. The Network page, usage history and the command line are unchanged. README says what the report can still contain: hardware names, drive serial numbers and volume labels.
5. **Saved history names.** `ProcessHistory.SavedName` decides the form a name is saved in:
   - Names that differ only in unpaired surrogates become one app, with U+FFFD in place of each.
   - "Everything else" (any case, `OrdinalIgnoreCase`), "Unknown application" and names containing `\`, `/` or `*` go to Everything else.
   - A name cut at 256 characters is trimmed again, so the saved form is stable.

   The store rejects a batch with any other name and writes nothing. Live grouping, End task's member set, the schema and existing rows are unchanged.
6. **Usage history keyboard (0.14.0 review #7, #12).**
   - #7: Left and Right on the CPU or RAM chart move one cursor, shown on both charts and matched by time. The minute refresh keeps the cursor at its time. Enter lists the bucket that is drawn. A click, Clear, Esc, or a range or period change replaces or clears the cursor.
   - #12: the Application resources rows are kept per app and updated in place. A minute refresh with the same apps keeps the row, its container, the current cell, keyboard focus and the scroll offset. A re-rank moves as few rows as possible.
7. **Docs.**
   - `docs/validation.md` gains PR 76's section "Shutdown test clocks and warm stores (tests only, 2026-11-05)" (`a594d5a`), with its stale last paragraph replaced.
   - It also records the 0.14.0 change to the graph periodic-flush test (`1a8893d`). That closes the ledger's deferred "GraphHistoryServiceTests timing fix", which shipped in 0.14.0 without a validation record.
   - `docs/releases/v0.13.0.md` drops "and must run before tagging". After the merge, the published v0.13.0 release text is replaced with that file.
8. **Test strength (test-only).** New and changed tests catch one-line regressions that the suite passes today:
   - Parser: the exact failure reasons, and bounds checks on cached names.
   - Tracker: CPU and read counters going backwards, and stale scans that become the next baseline.
   - Minute folder: the omitted I/O and memory in Everything else, and interval changes.
   - Processes table: every column key, the sum nulls, and the tie-break by name then PID.
   - End task: a `DriverStore` sibling folder.
   - History store: whole-day eviction across a full day, the integrity-check branch, and the one-day size at a 15-character machine key.
   - Shutdown: Quit draining process history, and the sign-out success trace.
   - Processes page: a real re-sort under selection, expansion and scroll; exact process-row cells; actions disabled while End task asks.
   - Usage history: Enter on a chart lists its bucket and leaves keyboard focus on the chart (the 0.14.0 Task 27 re-review gap; in Task 8, next to the cursor checks).
   - The disk gate measured at the shipped buffer size.

**Not in 0.14.1:**
- Orphan cleanup from `EtwNetwork.Start`, and retiring the disk trace when EtwDisk's own processing loop ends. Both are new behaviour on other paths: one handles a crash; the other handles a failure the page already shows and the switch already stops.

- The same unpaired-surrogate clash in `UsageHistoryStore`, where the second app's bytes are lost silently. Item 5 names only the process-history store. Deferred; when it is fixed, put the surrogate step in `UsageMinuteFolder`, not in the shared `UsageMetrics.NormalizeName`.
- Shell routing for Esc on Connections and Usage history, and the Usage history network Applications table being rebuilt each minute. Both are outside items 3 and 6 (#12 is the Application resources table).
- The same "must run before tagging" clause in `docs/releases/v0.11.0.md` and its published text, and a `docs/development.md` note on correcting published release text. Item 7 names only v0.13.0.
- `Omitted_carries_memory_byte_seconds` (its mutant is contrived), and a disk gate that also fails on any lost event.
- Three 0.13.0 deferred minors that the item 8 research routed to items 1–3, whose fixes do not touch them:
  - Task 6: a retire queued after closing can outlive `Collector.DisposeAsync` (`EtwDisk.cs:246`, `:262-266`). It is a disposal-during-pass timing window (a lossy take while disposal runs). The trace is still retired, only not awaited. Task 4's worker-exit stop runs after the worker's last `Take`, so it does not widen the window.
  - Task 14: a null image path for a just-exited process gives the generic "Could not open the file location." instead of "The process has already exited." Telling the two apart is a behaviour change outside item 2, which changes only the file check.
  - Task 17: Left on a process row selects its app and collapses it, and keyboard focus can leave with the removed row. That is one of the table's own keys, which item 3 keeps unchanged.

```markdown
## 0.14.1 — Processes and history fixes

- **Disk tracing stops when the collector does.** When DeadWare's collector stopped after an error ("Collector stopped (…). Restart DeadWare to retry."), the per-app disk trace, which runs only as administrator with Per-process monitoring on, kept running in Windows until DeadWare quit, and turning off Per-process monitoring did not stop it. It now stops with the collector, as the network trace already did.
- **Open file location tells a denied file from a missing one.** A program file that Windows denies DeadWare access to was reported as "The program file is no longer there." It now reads "Could not open the file location (denied by Windows)." and nothing is opened; a file Windows reports missing still reads "The program file is no longer there."
- **Processes shortcuts work right after opening the page.** Ctrl+F, F5 and Esc did nothing on the Processes page until something on the page had keyboard focus, so right after choosing **Processes** in the sidebar they were ignored. They now work whenever the page is shown, also while focus is in the sidebar or the page header.
- **Diagnostics no longer name apps.** When run as administrator, `--diagnose` output listed every app that used the network during the run, with its image name, PID and traffic. Each sample now gives only how many applications had attributed traffic, so the file contains no application names or program paths. The Network and Processes pages are unchanged.
- **Process history keeps recording with unusual app names.** Two programs whose names differed only in characters that are not valid Unicode were saved as the same name, and the clash stopped Application resources history until DeadWare restarted. They are now saved as one app, with � in place of each such character. A program named "Everything else", or with `\`, `/` or `*` in its name (Windows file names never contain these), counts in Everything else, so the history file holds only image names, never paths.
- **Usage history keyboard.** Left and Right on the CPU or RAM chart move the hairline on both charts, and the minute refresh no longer moves it back to the listed slot before you press Enter. The Application resources table keeps its selected row, current cell and keyboard focus when the page refreshes each minute.
```
