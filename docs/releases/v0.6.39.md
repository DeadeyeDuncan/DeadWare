- The Updates page no longer closes DeadWare when an installed app file or the saved rollback copy has been changed or damaged. It shows a message and disables installing until you reinstall the complete package.
- Old update downloads are now cleaned up when you open Updates. Only small records of the latest update are kept (its downloaded ZIP and unpacked copy are removed), and abandoned update folders older than a day are deleted. On the developer's machine this freed about 1 GB.
- Quit no longer hangs when a hardware sensor driver stops responding. DeadWare waits at most 5 seconds for hardware providers, while saving graph, Cooling Health, battery and connection history still finishes (up to 20 seconds). Connection history is now saved even if a hardware provider is stuck, including when Windows signs out.
- Starting as administrator at sign-in now requires DeadWare to be in a folder standard users can't change, such as `C:\Program Files\DeadWare`. A copy in a user folder (for example `AppData\Local\Programs` or Downloads) can't turn this on, and Settings explains why.
- If startup was already on from such a folder, Settings now shows a warning. Copy or extract DeadWare into `C:\Program Files\DeadWare` with administrator approval and choose **Enable / repair startup**, or turn startup off. Moving the folder with Explorer on the same drive keeps your account as its owner, so copy or extract it instead. Startup is never turned off automatically.
- A DeadWare installed in a protected folder (such as Program Files) updates through an administrator-only update folder, `%ProgramData%\DeadWare\updates`, so other programs can't tamper with a downloaded update. Updating such an installation needs **Restart as administrator**, and rolling back to a version older than 0.6.39 isn't available for it. Copies in user folders keep updating exactly as before from `%LOCALAPPDATA%\DeadWare\updates`.
- DeadWare and its updater ignore .NET startup hooks set through environment variables.

Existing updater-enabled installations can choose **Updates → Check for updates → Update & restart**. If you use startup as administrator from a user folder, check **Settings** for the new warning after updating.
