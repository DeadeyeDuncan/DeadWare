- **GPU and GPU memory per app.** The Processes page gains **GPU**, **GPU engine**, **GPU memory** and **Shared GPU memory** columns. GPU and GPU memory join the default columns; GPU engine and Shared GPU memory are in the column picker. As in Task Manager, an app's GPU is its busiest GPU engine on any adapter, **GPU engine** names it (for example "GPU 1 · 3D", with GPUs numbered in the order Windows lists its graphics adapters, which can differ from Task Manager's numbering), and GPU memory is dedicated video memory. A column list saved in 0.13 or 0.14 that still holds exactly the old defaults gains GPU and GPU memory once; a customized list is kept as it is.
- **Counter source.** The values come from Windows' GPU performance counters, behind **Per-process monitoring** (still off by default), and are expected to need no administrator rights; that has not yet been checked in a standard-user session. The counters are added by their English names (`\GPU Engine(*)\Utilization Percentage`, `\GPU Process Memory(*)\Dedicated Usage`, `\GPU Process Memory(*)\Shared Usage`), which is meant to work on a non-English Windows display language; that has not been tested. If reading them is slow on a machine with many GPU-using processes, DeadWare moves the read to its own loop. `--diagnose` gains a GPU summary of counts and timings only, which `--no-processes` also leaves out.
- **GPU in Application resources.** Usage history's Application resources saves each minute's top 10 apps by GPU as a fourth list (at most 40 apps plus Everything else), with **Rank by** GPU and the **Avg GPU** and **Avg GPU memory while listed** columns, and charts a selected app's GPU % of its busiest engine. Clicking a point on the Device **GPU** chart lists that moment's busiest apps by GPU, with a hairline on all three charts; a slot without GPU data says "No GPU data in this span." The history file's cap rises from 128 MiB to 192 MiB, and a full day at the 40-app cap measured 5.6 MiB. GPU history begins when 0.15.0 first runs; earlier minutes have no GPU data.
- **Returning to 0.14.x.** 0.15.0 upgrades `process-history.db` in place. 0.14.x cannot read the upgraded file: it shows "Application resource history unavailable (InvalidDataException)", or "(IOException)" for a file over 128 MiB, saves no application history and leaves the file untouched, until 0.15 or later is reinstalled, which reads it normally again.
